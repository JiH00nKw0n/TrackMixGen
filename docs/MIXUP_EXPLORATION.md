# 믹스업 방법론 초기 탐색 계획

이 문서는 TrackMix의 혼합(믹스업) 부분을 어떻게 설계해야 하는지를 탐색하는 실험의 목적, 고정 조건, 비교 상대, 통과
기준, 실행 절차를 적는다. 추종(tracking, 오차 적응 경로 추종)은 이 탐색에서 끈다. 저장소의 실행 방법은
`/README.md` 4장에, 방법 코드의 구조와 변형을 추가하는 절차는 `/tmg/generation/method/README.md`에 있다.

## 목차

1. 목적과 동기. 4장에서 관찰된 기준 생성기의 실패 원인 세 가지와, 믹스업이 그중 무엇을 고치려는 것인지.
2. 고정 조건. 생성기, 과제, 배치 범위, 관측, 정책, 추종 설정.
3. 믹스업의 설계 축. 원인별로 믹스업이 해야 할 일과 그 효과를 재는 지표.
4. 통과 기준. 생성 단계와 정책 단계에서 각각 믹스업이 보여야 하는 것.
5. 비교 상대. 기준 생성기와 "좋은 원본만 골라 쓰기" 조건들.
6. 실행 절차. 풀 생성, 시도 기록 분석, 데이터셋, 학습, 평가의 순서와 명령.
7. 지금까지 알려진 것. 2026-10-26 Square 시범의 혼합 발생 비율과 그 원인.
8. 구현이 필요한 것. 상위 k개 원본 제한 옵션.

## 1. 목적과 동기

MimicGen 계열 생성기는 사람이 시연한 원본 데모 몇 개(과제당 10개)의 구간을 새 물체 자세에 맞게 변형해 이어 붙여
합성 데모를 만든다. 4장에서 기준 생성기가 실패하는 원인은 세 가지로 관찰되었다.

- 원본마다 생성 성공률이 고르지 않다. 같은 과제에서 어떤 원본은 성공률이 높고 어떤 원본은 매우 낮다.
- 변형이 크다. 원본 구간을 새 물체 자세로 옮길 때 손 궤적이 크게 뒤틀려 집기나 끼우기가 실패한다.
- 조합의 앞뒤가 맞지 않는다. 앞 하위작업의 끝 자세와 뒤 하위작업의 시작 자세가 서로 다른 원본에서 와서 이어지지
  않는다.

믹스업은 선택된 원본의 구간을 다른 원본의 구간과 섞어 이 원인들을 줄이려는 수단이다. 따라서 "어떤 믹스업이 좋은가"는
"어느 원인을 겨냥했고, 그 원인이 실제로 줄었으며, 그 결과 정책 성능이 올랐는가"로 판단한다.

## 2. 고정 조건

| 항목 | 값 | 이유 |
|---|---|---|
| 생성기 | MimicGen (`generator=mimicgen`) | 접목과 기록이 가장 잘 검증된 생성기다 |
| 과제 | MimicGen 7개 중 선택 (`square`, `coffee`, `threading`, `stack_three`, `hammer_cleanup`, `mug_cleanup`, `three_piece_assembly`) | 모두 측정된 원본 순위가 있다 |
| 배치 범위 | `scene=ours` | 논문 실험의 범위다 |
| 관측 | 저차원 (`observation=low_dim`, 로봇 상태 + 물체 상태, 영상 없음) | 생성과 학습이 영상보다 약 10배 빠르다 |
| 풀 | `generation=pool_robosuite_lowdim` (영상을 그리지 않는 풀) | 저차원 학습에는 영상이 필요 없다 |
| 정책 | Diffusion Policy와 BC-RNN 둘 다 (`policy=diffusion_policy`, `policy=bc_rnn`) | 두 정책 모두에서 같은 방향의 결과가 나와야 한다 |
| 추종 | 끔 (`method.tracking.enabled=false`) | 믹스업의 효과만 본다 |
| 라벨 | 잡음 전 행동 (`labels: pre_noise`) | 모든 조건에 같게 둔다 |

## 3. 믹스업의 설계 축

| 겨냥하는 원인 | 믹스업이 해야 할 일 | 효과를 재는 지표 (시도 기록에서 계산) |
|---|---|---|
| 원본별 성공률이 고르지 않음 | 성공률 낮은 원본이 선택되면 성공률 높은 원본과 섞어 성공률 분포를 평평하게 만든다 | 원본별 생성 성공률의 분산, 가장 낮은 원본의 성공률 |
| 변형이 크다 | 변형이 작아지는 쪽으로 섞는다. 예를 들어 현재 물체 자세에 가까운 원본을 기증자로 고르거나, 기증자의 비중을 변형량에 따라 바꾼다 | 원본 구간과 변형된 구간 사이의 자세 차이(위치, 회전)의 평균 |
| 조합의 앞뒤가 맞지 않음 | 앞 구간의 끝 자세와 뒤 구간의 시작 자세가 이어지도록 기증자를 고르거나 경계 부분만 섞는다 | 하위작업 경계에서 손 자세의 불연속(위치 차, 회전 차) |
| 여럿 동시에 | 위 둘 또는 셋을 함께 점수로 묶어 기증자와 비중을 고른다 | 위 지표들을 함께 본다 |

지금 구현된 믹스업(`mixing.type: guided`)은 첫째 축만 겨냥한다. 순위 상위 절반을 성공률 높은 쪽으로 보고, 선택된
원본이 하위 절반이면 상위 쪽에서 손 방향이 허용각 안에 드는 기증자를 골라 비중 0.8 대 0.2로 섞는다. 둘째와 셋째 축은
새 클래스를 써야 한다.

## 4. 통과 기준

둘 다 만족해야 믹스업이 의미가 있다.

1. 생성 단계. 기준 생성기에서 성공률이 낮던 원본이 선택된 시도의 생성 성공률이 믹스업으로 올라야 한다. 시도 기록의
   `src_demo_inds`(선택된 원본)와 `success`로 원본별 성공률을 계산해 기준과 비교한다. 정책 학습 없이 풀만으로 본다.
2. 정책 단계. 믹스업 풀에서 만든 데이터셋으로 학습한 정책의 시험 장면 300개 성공률(학습 시드 3개 평균)이 기준 생성기 데이터셋의 정책보다
   높아야 한다. 데이터셋 크기(성공 데모 1,000개), 정책, 관측, 학습 시드는 같게 둔다.

믹스업이 실제로 몇 %의 하위작업에서 일어났는지를 먼저 확인해야 한다. 혼합 비율이 매우 낮으면 성능 차이는 믹스업의
효과가 아니다.

## 5. 비교 상대

믹스업은 성공률 높은 원본의 영향력을 늘리는 방식이므로, "좋은 원본만 쓰는 것"과 구분되어야 한다. 아래 조건을 같은
시도 수(또는 같은 성공 데모 수)로 만들고 같은 정책을 학습해 나란히 놓는다.

| 조건 | 뜻 |
|---|---|
| 기준 (`method=none`) | MimicGen 그대로, 원본 10개를 무작위로 선택 |
| 상위 1개만 | 순위 1위 원본만 선택 |
| 상위 3개만 | 순위 상위 3개 중에서 무작위 선택 |
| 상위 5개만 | 순위 상위 5개 중에서 무작위 선택 |
| 믹스업 변형들 | 3장의 축별 믹스업 |

믹스업이 "상위 k개만" 조건보다도 정책 성능이 좋아야 믹스업의 가치가 선다. 상위 k개 조건은 데모 다양성이 줄어드는
대신 생성 성공률이 오르므로, 어느 쪽이 정책에 더 중요한지도 이 비교에서 드러난다.

## 6. 실행 절차

조건 하나는 `configs/experiment/method/` 아래 파일 하나다. 모든 조건이 같은 명령을 방법 이름만 바꿔 돈다.

1. 조건 파일을 만든다. 값만 다른 변형은 `trackmix`를 상속해 바꿀 값만 적고 `tracking: {enabled: false}`로 둔다.
   새 선택 규칙은 `tmg/generation/method/`에 클래스를 쓰고 `interfaces.py`의 등록 사전에 이름을 넣은 뒤
   `mixing.type`으로 고른다. 절차와 뼈대 코드는 `/tmg/generation/method/README.md`에 있다.
2. 조립된 설정을 확인한다. `tmg show generate task=square scene=ours method=<이름> generation=pool_robosuite_lowdim`.
3. 풀을 만든다. 기준 풀과 과제의 순위 파일이 먼저 있어야 한다(믹스업이 순위를 읽는다).
   `make generate TASK=square SCENE=ours METHOD=<이름> GENERATION=pool_robosuite_lowdim CLUSTER=a100 OVERRIDES="generation.attempts=5000"`.
4. 시도 기록을 먼저 분석한다. `chunks/seed<N>/records/attempts.jsonl`에 시도별 성공, 선택된 원본, 하위작업별 혼합 기록
   (`mixed`, `source_a`, `source_b`, `identity_reason`)이 있다. 원본별 성공률, 혼합 발생 비율, 혼합하지 않은 이유의 분포를
   기준과 비교한다. 이 단계에서 4장의 기준 1을 판정한다.
5. 데이터셋, 학습, 검증, 시험을 같은 방법 이름으로 돈다.
   `make dataset ... METHOD=<이름> OBSERVATION=low_dim OVERRIDES="size=1000"`,
   `make train ... POLICY=bc_rnn` 과 `POLICY=diffusion_policy`,
   `make validate`, `tmg select_checkpoint`, `make evaluate`. 한 과제의 전체 묶음은 `scripts/task_policy_pipeline.sh`가 돈다.
6. 결과는 실행 폴더의 `eval/test/<체크포인트>/eval_summary.json`에 성공률과 95% 신뢰구간으로 남는다.

## 7. 지금까지 알려진 것

2026-10-26, Square, `scene=ours`, 20회 시범(`mixup_only`)에서 혼합은 하위작업 40개 중 2개에서만 일어났다. 혼합하지 않은
이유는 "선택된 원본이 상위 절반" 22건, "허용각 안의 기증자 없음" 16건이었다. Square는 너트의 요 각도가 0에서
360도까지 흩어져 원본마다 손 방향이 크게 다르므로, 손 방향 허용각 20도가 거의 모든 기증 후보를 걸러냈다. 따라서 첫
탐색은 허용각(20도, 40도, 90도, 제한 없음)에 따른 혼합 발생 비율과 생성 성공률의 변화부터 보는 것이 맞다.

기준 생성기의 과제별 생성 성공률(`scene=ours`)은 Coffee 47.9%, Threading 17.6%, Hammer Cleanup 16.1%, Mug Cleanup 12.7%,
Stack Three 11.7%, Square 7.3%, Three Piece Assembly 6.5%다. 원본별 순위와 성공률은
`configs/experiment/generator/mimicgen/ranking/<과제>.yaml`에 있다.

## 8. 구현이 필요한 것

"상위 k개만 쓰기" 조건은 아직 구현되어 있지 않다. 원본 선택을 순위 상위 k개로 제한하는 옵션(예를 들어 방법 파일의
`sources: {top_k: 3}`)을 MimicGen 어댑터의 원본 선택 지점에 추가해야 한다. 순위 파일은 이미 있으므로 선택 집합만 바꾸면
된다. 변형이나 조합을 겨냥한 믹스업(3장의 둘째, 셋째 축)도 새 클래스가 필요하다.
